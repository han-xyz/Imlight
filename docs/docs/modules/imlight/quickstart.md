# Quickstart Guide

## Addressing The Gap

In the [shared data article](../imlight/concepts/shared-data-systems.md), it's discussed that the server and game client share the same data for mutual understanding. This does, however, lead to plenty of gaps in data where only the server uses a section of data. Sometimes this data still ships with the game client, other times it does not.

*There is no way for the server to know the missing information unless it is manually created.*

Creating a server using Imlight requires filling in these gaps with your own data. Imlight loads this information from a [data pack](#world-data-spiraldb-data-pack), a git repository of JSON files. 

That repository and the data it contains is referred to as a "data pack".

**If you do not recreate this data, you will notice missing functionality in your server:**
- Where gateways lead (zone transfers)
- NPC spell decks
- NPC shopkeeper inventories
- Drop tables
- Quests

### Bring Your Own Data
**Imlight does not, and never will ship with a "data pack" of this information. Implementation teams must create and maintain their own data packs to fill these gaps.**

**Implementations and derivatives using Imlight are required to follow the same [BYOD](./index.md#about) philosophy and must not distribute any copyrighted game files, game data, or data packs.**

### Data Pack Disclaimers
:::tip
Revive101 has developed a tool to help manually recreate this data called [Imview](https://github.com/Revive101/Imview). This tool is an over-arching tool to manage Imlight as a whole, but includes a subset of features to help with data creation. It is highly recommended to use this tool to help with data creation.

If you are part of a team, you share your data pack by sharing its git repository.
:::
:::warning
It is impossible to know precisely how the original servers handled server-side data. Imlight must make informed assumptions about the original server behavior. Consequently, certain data or the way it is processed may differ from the original implementation and may not be entirely accurate.
:::
:::info
In may be possible in the future that zone transfers can be automatically generated by analyzing game data. It has not been explored yet.
:::
:::info
It's been observed that in some game revisions, NPC spell decks are shipped with the client. However, this does not always happen and cannot be relied upon.
:::

## Prerequisites

**Development Environment**
- **.NET 10 SDK** - Required for building Imlight and Imcodec
- **Git** - For cloning repositories and managing submodules

**External Tools**
- **[WizType](https://github.com/wizspoil/wiztype)** - Extract type definitions from game client
- **[Aurorium](https://github.com/Revive101/Aurorium)** - Self-hosted patch server

Node.js is only needed to build this documentation site (`cd docs && npm ci && npm run docs:build`).

## Core Setup

### 1. Clone Imlight Repository

```bash
# Clone with Imcodec submodule
git clone --recurse-submodules https://github.com/Revive101/Imlight.git

# Or if already cloned, initialize submodules
cd Imlight
git submodule update --init --recursive
```

### 2. Prepare Imcodec Source Generation

Imcodec requires game data files to generate strongly-typed C# classes at compile time. If you'd like an in-depth reading on why, see the [Imcodec](../imlight/concepts/imcodec.md) documentation.

**Type Definitions**
1. Use [WizType](https://github.com/wizspoil/wiztype) to extract type definitions from your game client
2. Save the generated JSON file to:
   ```
   submodule/Imcodec/src/Imcodec.ObjectProperty/GeneratorInput/
   ```

**Message Definitions**
1. Extract `Root.wad` from your game client using Imcodec itself:
   ```bash
   # needs generator inputs: the WizType JSON must already be in the ObjectProperty GeneratorInput folder
   dotnet run --project submodule/Imcodec/src/Imcodec.Cli wad unpack Root.wad
   ```
2. Locate XML files matching `*Messages*.xml` pattern
3. Copy all message XML files to:
   ```
   submodule/Imcodec/src/Imcodec.MessageLayer/GeneratorInput/
   ```

### 3. Build Imlight

There is no solution file at the repository root; build from `src/`. (needs generator inputs)

```bash
dotnet build src/Imlight.sln

# Or for release build
dotnet publish src/Imlight.Director/Imlight.Director.csproj -c Release
```

:::tip
Imlight may fail to build with errors about missing types or messages. If you are certain you've put the correct files in the GeneratorInput directories, build the Imcodec project first to ensure the source generation completes successfully.
:::

### 4. Run Imlight

Imlight reads `Config/Imlight.ini` relative to its working directory, so start it from the Director project folder (needs generator inputs):

```bash
cd src/Imlight.Director
dotnet run
```

## Configuration

Edit `src/Imlight.Director/Config/Imlight.ini`.

### Configuration overrides

Any key can be overridden with an environment variable named `IMLIGHT__<Section>__<Key>`. The variable wins over the ini file. Write each space in the section name as `_`:

```bash
# sets GameServerIP in [Game Server]
IMLIGHT__Game_Server__GameServerIP=10.0.0.5
```

A variable that starts with `IMLIGHT__` but does not have a section and a key is logged as a warning and ignored.

### Admin account

The server refuses to start when `AdminAccountPassword` in `[Database]` is empty or a known default: the old `compsci`, or a password that older builds hard-coded (the list is `AdminCredentialPolicy.KnownDefaultPasswords`). Set it in the ini or with `IMLIGHT__Database__AdminAccountPassword`. `AdminAccountUsername` defaults to `admin`.

The admin account is created on first boot only. Changing the credentials later does not change an existing account, with one exception: when boot finds an Administrator that still has a known default password, it resets the account named in `AdminAccountUsername` to the configured password and refuses to start for any other such account. To clear a refused account, set `AdminAccountUsername` to it for one boot so it is reset, then rename again, or delete it from the player database.

### Player database

Player accounts and characters live in **RavenDB**. With `PlayerDatabaseUrl` empty, Imlight starts an embedded RavenDB.

```ini
[Database]
# Leave empty for the embedded database
PlayerDatabaseUrl =
PlayerDatabaseName = Playerdata
# Required for a remote database; resolved from the working directory
PlayerDatabaseCertificatePath = ../playerdb-dev-1yr.pfx

# Embedded database settings
EmbeddedDatabaseDataDirectory = ../ImlightEmbeddedDatabase/
EmbeddedDatabasePort = 8080
```

For a remote database, set the URL and place the certificate at `PlayerDatabaseCertificatePath`.

### World data (SpiralDB data pack)

Imlight fetches the data pack from a git repository (the SpiralDB format) into a local clone:

```ini
[Database]
# Your fork of the data pack
SpiralDBRemoteUrl = https://github.com/Revive101/spiraldb.git
SpiralDBBranch = main
# Local clone location, relative to the working directory
SpiralDBLocalPath = ./spiraldb-cache
# Fetch the latest commit on boot
SpiralDBAutoFetch = true
# Use the local clone only and never contact the remote
SpiralDBDisableRemote = false
```

Workflow: fork the SpiralDB repository, edit the data with [Imview](https://github.com/Revive101/Imview), commit and push to your fork, and Imlight fetches it on the next boot. Point `SpiralDBRemoteUrl` at your fork.

### Crown shop

What the crown shop sells comes from the data pack: every `CrownShop/*.json` tab file under `SpiralDBLocalPath`, with each item's gold and crowns price. An item with a price of `0` in a currency cannot be bought with that currency. A malformed tab file or a negative price stops the server at boot; on a hot reload the previous catalogue stays live and the error is logged.

| Key in `[CrownShop]` | Default | Meaning |
| --- | --- | --- |
| `Enabled` | `true` | Load the catalogue at boot; with `false` the shop is empty |
| `AutoReloadOnChanges` | `true` | Reload the catalogue when a tab file changes |
| `WishlistMaxSize` | `30` | Most items a wishlist may hold; a larger wishlist is not saved |
| `WishlistSBExpansionSize` | `10` | Extra wishlist slots the client shows to subscribers |
| `MaxBuyCount` | `100` | Most copies of an item one purchase may buy |

```bash
# sets MaxBuyCount in [CrownShop]
IMLIGHT__CrownShop__MaxBuyCount=10
```

A gift can be sent to any character, not only the sender's friends.

Set your own crown balance with `.mod setcrowns <amount>` (Quality Assurance and above).

## Patch Server Setup

Imlight and the game client must source files from the same location.

### Self-Hosted Patch Server

1. Set up [Aurorium](https://github.com/Revive101/Aurorium) patch server
2. Update configuration:
   ```ini
   [Patch Server]
   PatchServerInternalUrl = http://your-patch-server.com
   ```
3. Set `GameRevision` in `[Global Settings]` to the revision Aurorium mirrored. Aurorium reports it at its `/latest` endpoint with a `V_` prefix (`V_r806919.Wizard_1_610`); write it without the prefix (`r806919.Wizard_1_610`).

## Docker

The image is built from the repository root, with the Imcodec submodule initialised (`git submodule update --init --recursive`) and your generator inputs in `deploy/generator-input/` (see its README for how to produce them; the folder is gitignored):

```bash
docker build -f deploy/Dockerfile -t imlight .
```

The build stops with a message when the folder has no `*.json` or no `*Messages*.xml`. A successful build needs generator inputs.

| Item | Value |
| --- | --- |
| Ports | `12000` login, `12333` game (one per realm), `12500` patch |
| Volumes | `/data/db`, `/data/spiraldb`, `/data/logs`, `/data/cache` |
| Game server address | Set `IMLIGHT__Game_Server__GameServerIP` to the address clients connect to; the default `127.0.0.1` sends remote clients to their own machine |
| Admin password | Not in the image; pass `IMLIGHT__Database__AdminAccountPassword` |

The image sets `IMLIGHT__*` defaults for the data paths, `Patch_Server__PatchServerInternalUrl` (`http://aurorium:12369`), one realm (`Centaur`), `GameRevision`, and `LogLevel`. Override any of them with `-e`. Do not publish the embedded RavenDB port (`8080`) or the Akka remote port (`12999`).

The full stack (Imlight, Aurorium and their volumes) is defined in the `revive101-server` compose repository.
